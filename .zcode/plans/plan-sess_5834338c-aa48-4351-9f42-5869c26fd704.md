# 流水线打包规则失效与状态卡在57%的架构深度分析与修复方案

## 一、 根本原因深度分析 (Root Cause Analysis)

### 1. 设置中的打包规则未生效的根本原因
- **`Pipeline.run_one` 规则短路缺陷 (`scripts/workflow/pipeline.py:241-256`)**：
  在流水线启动单项目处理时，`Pipeline.run_one` 直接从 `project_config` 或 `config.get("build_commands")` / `config.get("build_command")` 取值并赋给 `ctx.extra["build_command"]`，**完全遗漏了 `branch_build_commands` 的分支规则匹配调用**。
- **`step_fns.py:171-174` 的屏蔽效应**：
  ```python
  build_cmd = ctx.extra.get("build_command") or resolve_branch_build_command(ctx.config, ctx.project_name, ctx.branch)
  ```
  由于 `ctx.extra["build_command"]` 在 `pipeline.py` 中已被赋予了项目级或全局默认命令（或默认 `deploy.sh`），此处的 `or` 短路导致 `resolve_branch_build_command` 永远不会被执行，用户在“设置”中配置的分支打包规则被彻底无视。
- **分支匹配模式缺陷 (`scripts/git/build_cmd.py:268`)**：
  原代码仅支持 `pattern.endswith("*")` 的最简前缀匹配，不支持大小写不敏感匹配以及多通配符，且当找不到指定脚本时自动探测回退到 `package.json` 的通用脚本，导致执行行为与预期规则不一致。

### 2. 内容实际已上传但界面仍卡在“执行项目打包 (57%) 处理中”的原因
- **流水线步骤比例**：
  流水线共有 7 个步骤，前 4 步完成后，第 5 步处于 running 时完成度为 $\frac{4}{7} \approx 57\%$。
- **打包脚本内含部署与子进程挂起**：
  如果构建脚本自身包含了上传/复制逻辑，远端内容虽然已经上传，但脚本中启动的后台子进程（如 webpack 守护、未退出的 npm/node 管道句柄）未释放 stdout/stderr，导致 `run_process_stream` 阻塞等待进程退出直至超时（600 秒）。
- **WebSocket 日志拥塞导致订阅被踢出**：
  `task_manager.py` 中订阅者队列大小固定为 1000，高频构建日志在 Windows 下触发 `QueueFull` 导致订阅者被丢弃 (`_subscribers.discard`)，后续的 `step-end` / `done` 事件丢失，前端一直停留在 running 状态。

## 二、 架构修复与优化方案

### 1. 修复命令解析与规则继承链路
- **修改 `scripts/workflow/pipeline.py`**：
  在 `Pipeline.run_one` 中，优先通过 `resolve_branch_build_command(self.config, name, branch)` 解析有效命令，仅在 `project_config` 明确传递自定义命令时覆盖。
- **增强 `scripts/git/build_cmd.py`**：
  - 增强 `resolve_branch_build_command`：支持不区分大小写的匹配、`fnmatch` 灵活通配符匹配（如 `release/*`, `feat-*`）、以及更健壮的层级回退（分支规则 -> 项目规则 -> 全局规则 -> 智能检测）。
  - 在执行构建时向环境变量中注入 `BRANCH_NAME`、`BUILD_BRANCH`，方便构建脚本和 npm scripts 读取。
- **同步修复 `scripts/workflow/step_fns.py`**：
  保持 `step_build` 与 `step_select_artifact` 的候选产物路径及构建命令一致。

### 2. 修复进程超时流转与 WebSocket 事件同步
- **优化 `scripts/server/task_manager.py`**：
  WebSocket 广播采用滑窗环形缓冲或丢弃旧日志策略 (`q.get_nowait()` + 重新入队)，防止日志过大时订阅者被直接丢弃导致状态丢失。
- **增强构建输出与进程回收 (`scripts/git/build.py` / `scripts/tools/exec.py`)**：
  确保构建超时（可配置）与进程树的正确销毁。

## 三、 测试与多轮验证计划 (QA Plan)

1. **第 1 轮：单元测试与规则解析测试**
   - 编写/运行 `pytest scripts/tests/test_branch_build_commands.py` 和 `test_build_cmd.py`。
   - 验证分支精准匹配、通配符匹配、大小写不敏感匹配、多层级回退优先级。
2. **第 2 轮：流水线步骤与状态同步测试**
   - 模拟执行 `Pipeline.run_one`，验证 `ctx.extra` 正确注入了分支规则解析后的命令。
   - 模拟高频日志推送，验证 WebSocket 队列溢出保护机制，确保 `step-end` 和 `done` 事件 100% 触达前端。
3. **第 3 轮：端到端与异常流程回归测试**
   - 验证前后端打包规则的保存与读取闭环。
   - 验证构建产物检测与 SVN 上传步骤无缝衔接。
