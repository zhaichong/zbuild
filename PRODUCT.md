# Product

## Register

product

## Users

The primary user is the developer who maintains this local packaging and upload tool. They use it to select projects and branches, run builds, and publish verified artifacts without repeatedly switching to command-line workflows.

## Product Purpose

Provide a dependable desktop workflow for building frontend projects and uploading the resulting artifacts. Clear status, recoverable failures, and visible progress matter more than configuration density.

## Brand Personality

Practical, reassuring, and cute. The interface should reduce the tension of release work while keeping the build state unambiguous.

## Anti-references

Avoid noisy gaming-dashboard visuals, decorative motion that obscures work status, and alerts that imply a failure when the pipeline completed successfully.

## Design Principles

1. Make the real pipeline outcome unmistakable.
2. Keep release actions calm and focused.
3. Use the desk pet to add warmth, never as the only status signal.
4. Preserve familiar controls and safe defaults.

## Accessibility & Inclusion

Respect the operating system's reduced-motion preference. Pair color with text and icons for status, and keep settings labels direct and readable.
