# 多项目打包发布 Spec

## 目标

提供一个可实际使用的桌面发布工具：用户可选择一个或多个项目，为每个项目选择 Git 分支，依次完成代码同步、依赖安装、打包，并将产物上传到所选目标。

## 已知事实

- 项目是 Vue 3 + Electron 前端、Python 执行器。
- 已有项目发现、分支选择、多项目流水线、服务器上传、SVN 上传和本地输出实现骨架。
- 当前上传目标模型为三选一：`server`、`svn`、`local`。
- 当前工作区包含大量未提交改动，实施时必须保留，不得重置或覆盖。
- 当前 Windows 包会包含本机 `references/tool-config.json` 和 `references/history/*.json`；已确认配置中存在非空 SVN 密码字段，必须在交付前排除这些运行数据。
- 打包后 Python 执行器优先查找内置 Python，否则依赖目标机器的 `py -3`；最终包必须明确满足该运行时条件。

## 用户主路径

1. 配置项目根目录、构建参数和上传目标凭据。
2. 刷新并勾选一个或多个项目。
3. 为每个项目选择分支及目标路径。
4. 在确认页检查项目、分支和发布目标。
5. 顺序执行各项目的切分支、拉取、构建和上传。
6. 界面逐项目展示成功或失败，并允许仅重试失败项目。

## 外部副作用与安全边界

- Git：允许读取状态、切换/拉取用户选定分支；存在本地改动时必须先让用户选择取消、跳过或 stash。执行结束后应恢复原分支，并在选择 stash 时恢复本地改动。
- 服务器：仅在用户最终确认后上传到明确配置的主机和目录。
- SVN：仅在用户最终确认后写入明确计算出的目标 URL；不得在日志或历史记录中保存明文密码。
- 打包：安装包/免安装目录不得包含开发机配置、凭据、历史记录或调试日志；用户运行配置必须写入独立、可持久化的用户数据目录。
- 多项目默认顺序执行，单项目失败不覆盖其错误信息；是否继续后续项目沿用现有流水线行为。

## 验收标准

- AC-01：界面能发现多个项目，并可勾选任意一个或多个项目进入同一次运行。
- AC-02：每个已选项目可独立查看并选择 Git 分支，确认页显示最终分支。
- AC-03：每个项目按其配置执行构建，成功后得到存在且非空的产物；构建失败时不得上传。
- AC-04：选择“服务器”目标时，各项目产物上传到对应服务器路径，缺少主机、凭据或项目路径时在执行前阻止运行。
- AC-05：选择“SVN”目标时，各项目产物上传并提交到对应 SVN 目录，缺少 SVN 根地址、凭据或业务必填项时在执行前阻止运行。
- AC-06：一次选择多个项目时逐项目记录结果，总结成功数和失败数，并可仅重试失败项目。
- AC-07：项目有本地改动时不会静默丢失；运行结束后恢复执行前分支，选择 stash 时恢复原本地改动。
- AC-08：前端 `typecheck`、`lint`、生产构建和 Python 自动测试通过，Electron 可生成 Windows 安装包或免安装目录。
- AC-09：验证阶段只使用本地/模拟目标；真实服务器上传和 SVN 提交必须再次获得用户明确授权。
- AC-10：检查 `app.asar` 内容可证明不含 `tool-config.json`、运行历史、明文凭据或开发机路径；应用重启后仍能从用户数据目录读取其配置。
- AC-11：在无开发环境的 Windows 包中，Python 运行时可用；若不内置 Python，则界面必须在运行前明确检测并报告缺失条件。

## 非目标

- 不引入并行构建、任务队列、远程调度或新依赖。
- 不自动创建 Git/SVN 分支。
- 不在本轮自动部署、提交 SVN、推送 Git 或发布安装包。

## 默认解释与待确认项

- 默认解释：每次运行选择一个上传目标（服务器或 SVN），不是同一份产物在一次运行中同时上传两处；这与现有最小实现一致。
- 待确认：如果你要求“一次运行同时上传服务器和 SVN”，需要把当前互斥模式改为多目标流水线，验收范围会相应扩大。
