# 依赖持久化缓存与跳过重复安装修复方案

## 1. 问题根因分析
在 Web 任务调度架构中，每个任务都会生成一个独立的临时 Git worktree 工作区（路径为 `data/workspaces/<task_id>/<project_name>`）：
1. **工作区隔离无历史依赖**：新创建的 worktree 是全新的干净目录，没有 `node_modules`；
2. **指纹校验失效**：由于没有 `node_modules` 和 `.zbuild_deps_fingerprint`，系统每次都被迫执行完整 `npm install`；
3. **构建结束销毁目录**：任务结束后 `WorkspaceManager.cleanup` 直接删除了整个临时目录，导致新安装的 `node_modules` 被销毁，下一次构建又必须重新下载安装。

---

## 2. 核心架构设计

通过**项目级持久化依赖池 + 零拷贝目录联接（Junction/Symlink）**机制实现跨任务依赖持久复用：

```
全局持久化依赖池：
  D:\zbuild\.zbuild-data\deps_cache\<project_name>\node_modules
                        ▲
                        │ (NTFS Junction / Symlink 联接)
                        ▼
任务临时工作区：
  D:\zbuild\.zbuild-data\workspaces\<task_id>\<project_name>\node_modules
```

---

## 3. 具体修改计划

### 步骤 1：在 `WorkspaceManager` 中增加持久化依赖池管理 (`scripts/server/workspace.py`)
1. **初始化依赖缓存根目录**：
   - 增加 `self.deps_cache_root = self.data_dir / "deps_cache"`，并自动创建该目录。
2. **工作区准备阶段 (`prepare`)**：
   - 在为项目创建 Git worktree 之后，检查项目若包含 `package.json`（或前端项目特征）：
   - 确保 `deps_cache/<safe_project_name>/node_modules` 存在；
   - 在工作区内创建指向该缓存目录的目录联接（Windows 下采用无需管理员权限的 NTFS Junction，Linux/macOS 下采用 Symlink）。
3. **安全清理阶段 (`cleanup` / `_remove_task_root`)**：
   - 在调用 `git worktree remove` 和 `shutil.rmtree` 之前，先解除 worktree 中的 `node_modules` 链接（仅删除链接本身，严禁删除目标真实缓存目录），确保全局依赖池安全保留。

### 步骤 2：优化依赖指纹与日志输出 (`scripts/git/deps.py`)
1. **扩展锁文件指纹检测**：
   - 在 `dependency_fingerprint` 中除 `package.json`、`package-lock.json`、`.npmrc` 外，补充支持 `yarn.lock` 和 `pnpm-lock.yaml`；
2. **增强前端实时日志**：
   - 当指纹匹配成功跳过安装时，调用 `on_line("⚡ 依赖未发生变动 (指纹匹配)，跳过依赖安装")`，使控制台和前端界面清晰可见 0 秒跳过；
3. **健壮性保障**：
   - 当 `node_modules` 是软链/联接且指纹匹配时，直接返回 `True`，不执行任何子进程。

### 步骤 3：编写与完善单元测试
1. 在 `scripts/tests/test_workspace_manager.py` 中增加对 `node_modules` 持久化链接与清理保护的测试用例；
2. 在 `scripts/tests/test_deps.py` 中补充扩展锁文件与跳过日志回调的测试用例；
3. 运行全量测试，确保所有测试用例通过。

---

## 4. 验证方式
1. 运行 `python -m unittest discover scripts/tests` 验证所有单元测试通过；
2. 验证两次连续执行相同项目的构建时，第二次构建输出 `依赖未发生变动 (指纹匹配)，跳过依赖安装`，且耗时为 0 秒。
