# 方案 1：基于依赖指纹的多版本 node_modules 缓存池实施方案

## 1. 核心目标
解决每次打包在独立隔离的 workspace (`.zbuild-data/workspaces/<task_id>`) 下重复下载和安装依赖速度慢的问题。
- **构建隔离**：继续保持每个打包任务工作区完全隔离（detached worktree + junction）。
- **秒级复用**：按 `package.json` + `package-lock.json` 等依赖指纹划分多版本缓存槽位，同一依赖版本的任务直连挂载已有 `node_modules`，**0 秒跳过依赖安装**。
- **分支切换免重装**：项目在分支 A 和分支 B 频繁切换时，分别挂载各自对应的依赖版本槽位，互不覆盖。
- **离线与镜像加速**：新依赖安装时配置全局 `npm_cache` 目录及 `--prefer-offline`，大幅缩减首次依赖下载时间。
- **自动防膨胀与并发安全**：加入依赖槽位安装锁与 LRU 自动清理（保留最近活跃版本）。

---

## 2. 详细设计与改动清单

### (1) 依赖指纹与槽位计算 (`scripts/git/deps.py`)
- **`compute_deps_slot_key(project_path: Path) -> str`**：
  - 提取 `package.json`、`package-lock.json`、`yarn.lock`、`pnpm-lock.yaml`、`.npmrc` 的内容哈希。
  - 生成 16 位短哈希（如 `a8f3b2c1d0e9`）；无 `package.json` 时返回空。
- **离线优先与性能优化参数**：
  - `_node_env()` 中配置全局 npm 缓存路径 `npm_config_cache` 指向 `.zbuild-data/npm_cache`。
  - `dependency_install_command()` 中增加 `--prefer-offline --no-audit --no-fund --progress=false`。
- **跨进程/并发安装保护**：
  - 在依赖槽位安装时，写入临时的 `installing.lock` 文件并在完成时移除，避免多任务同时向同一个槽位并发写入。

### (2) 多版本缓存池管理与挂载 (`scripts/server/workspace.py`)
- **目录结构升级**：
  - 将原有的单目录 `deps_cache/<project>/node_modules`
  - 升级为多版本缓存池：
    ```
    .zbuild-data/
      deps_cache/
        <project_name>/
          <slot_hash>/
            node_modules/
            package.json
            package-lock.json
            postcss.config.js
            ... (Webpack/PostCSS 配置文件)
            .last_accessed (访问时间戳，供 LRU 淘汰)
      npm_cache/ (全局 npm tarball 离线缓存)
    ```
- **工作区准备 (`prepare`)**：
  -检出 worktree 后，计算当前分支的依赖槽位哈希 `slot_key`。
  - 若存在 `package.json`，创建槽位目录并更新 `.last_accessed`。
  - 通过 Windows Junction（`mklink /J` / `_winapi.CreateJunction`）将 `worktree / "node_modules"` 挂载至 `deps_cache/<project>/<slot_key>/node_modules`。
  - 将项目构建配置（`postcss.config.js`、`babel.config.js` 等）同步到对应槽位根目录，防止 loader 跨目录解析失真。
- **LRU 缓存淘汰 (`prune_deps_cache`)**：
  - 增加 `prune_deps_cache(max_versions_per_project=5, max_age_days=15)` 方法，按 `.last_accessed` 排序，自动清理超出保留上限的历史旧版本依赖目录。

### (3) 自动维护调度 (`scripts/server/task_manager.py`)
- 在每日定时清理后台循环 `_maintenance_loop` 中，调用 `await self.workspace.prune_deps_cache()`，定期释放陈旧依赖占用的磁盘空间。

### (4) 自动化测试 (`scripts/tests/test_deps_cache.py`)
- 编写针对多版本指纹槽位、Junction 挂载/卸载、指纹命中跳过、LRU 清理的完整单元测试，确保高可靠性。

---

## 3. 验证步骤
1. 运行单元测试：`pytest scripts/tests/test_deps_cache.py -v`
2. 运行完整测试套件：`pytest scripts/tests/ -v`
3. 模拟同一项目不同分支（相同/不同依赖）的打包任务，验证：
   - 依赖相同时：日志显示 `⚡ 依赖未发生变动 (指纹匹配)，跳过依赖安装`，0 秒完成；
   - 依赖不同时：各自挂载不同槽位，再次切换回原分支无需重新下载。
