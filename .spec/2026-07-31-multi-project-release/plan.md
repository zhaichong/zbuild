# Plan：多项目打包发布

> 对应：`spec.md`
> 流程档位：Standard

## 方案概述

保留现有 Vue/Electron → Python Pipeline → Git/Build/Uploader 调用链，只修根因和补证据：运行数据移到 Electron 用户数据目录；打包排除本机状态；流水线统一恢复分支；使用临时 Git 仓库和伪造上传边界验证多项目、服务器与 SVN 路径，不连接真实外部系统。

## 影响范围

| 动作 | 文件/模块/数据 | 关联 AC | 说明 |
|---|---|---|---|
| 修改 | Electron/Python 运行时路径与打包清单 | AC-08, AC-10, AC-11 | 排除本机状态并持久化用户配置 |
| 修改 | Pipeline/Git 分支恢复 | AC-02, AC-06, AC-07 | 成功失败都恢复执行前状态 |
| 补测 | Pipeline、构建、服务器与 SVN uploader | AC-01–AC-07, AC-09 | 本地临时目录/替身，无网络写入 |
| 验证 | 类型检查、Lint、Python 测试、Vite/Electron 打包 | AC-08–AC-11 | 审计最终 app.asar |

## 风险与缓解

| 风险 | 级别 | 缓解措施 | 回滚/恢复 | 是否需确认 |
|---|---|---|---|---|
| 打包携带凭据 | 高 | 明确排除运行文件并自动审计包内容 | 删除生成包并恢复打包清单 | 否，修复已在 Spec 确认 |
| Git 本地改动丢失 | 高 | 临时仓库集成测试覆盖 stash/分支恢复 | 保留 stash，失败时报告而不静默 | 否 |
| 服务器/SVN 产生真实写入 | 高 | 自动验证仅使用替身，真实执行保持确认门禁 | 无外部写入无需回滚 | 是，真实执行前 |
| 现有脏工作区混入 | 中 | 只改目标文件、不切分支、不自动提交 | 按文件审查最小 diff | 否 |

## 数据与调用链

```text
Vue 选择项目/分支/目标 → Electron IPC → Python Pipeline
  → 每项目 Git 切换/拉取 → deploy.sh → 选择 tar.gz
  → server(SFTP+SSH) 或 SVN(checkout+commit)
  → 逐项目结果/历史（脱敏） → UI 汇总
```

## 关键选择

- 选择与理由：沿用每次运行单上传目标及顺序多项目执行，最符合现有结构且避免引入队列/并发。
- 替代方案未采用：一次同时上传服务器和 SVN；用户确认的默认 Spec 未要求多目标同跑。

## 验证策略

| 验证层级 | 覆盖 AC | 方法 | 回归关注点 |
|---|---|---|---|
| 单元 | AC-03–AC-05, AC-10 | 路径、脱敏、命令生成测试 | 凭据、目录边界、失败不上传 |
| 集成 | AC-01, AC-02, AC-06, AC-07 | 临时 Git 仓库运行多项目 Pipeline | 分支/stash 恢复、逐项目结果 |
| 构建 | AC-08, AC-11 | typecheck/lint/test/build/pack | Windows 包可生成、Python 检测 |
| 包审计 | AC-10 | 列出 app.asar 并扫描敏感运行文件 | 配置、历史、开发机路径 |

## 范围外

- 并行构建、远程任务调度、新依赖、自动创建分支、真实上传执行。

## Strict 执行门禁

不适用；本任务采用 Standard。真实服务器/SVN 外部写入仍保留独立确认门禁。
